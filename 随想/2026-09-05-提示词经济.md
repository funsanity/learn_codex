# 做完一个小游戏，我开始理解“Prompt Economy”

这两天测试了一下 GPT-6，顺手用它做了一个小游戏，一天就完成了。

![使用 GPT-6 一天完成的小游戏实机截图](./gpt-6-mini-game-demo.png)

*图：这次使用 GPT-6 开发的小游戏。*

最直观的感受是：它更能听懂人话了。从想法到功能，再到 UI 细节，整体都比较顺。以前需要反复解释、来回纠正的地方，这次少了很多。功能实现和需求对齐都不错，脑子里的主意，终于能比较连贯地变成屏幕上的东西。

但用下来，另一个感受同样强烈：太贵了。

和 GPT-5.6 相比，我的实际使用感受是：完成类似的工作，GPT-6 的花费达到原来的 3 倍以上。这是个人体感，不是官方单价对比。能力确实强，Token 也确实烧得快，已经贵到让我在每次追加需求前，都会想一下：这一轮值不值？

这让我冒出一个念头：以后，我们可能会进入“Prompt Economy”。

今天谈 LLM 成本，大家习惯看 Token。它像电表上的度数，方便计量和收费。但真正影响这笔钱花得值不值的，是我们如何提出问题、组织 Context，以及告诉模型什么叫“做完了”。

同样是做小游戏，一句“帮我做个好玩的游戏”，模型要替你猜玩法、定风格、补规则。猜错了，再推倒重来。如果提前说清核心玩法、操作方式、UI 要求和 Acceptance Criteria，很多无效消耗就能省下来。

Prompt 的价值，就在这里：把模糊的主意，变成可以执行的任务。

再往下看，会发现 Prompt 已经不只是聊天框里的一段话。Project Rules、SKILL、Workflow，甚至一部分 Agent Governance，都在用自然语言描述：该做什么、先做什么、什么时候停下来、如何检查结果。

当然，它们也不全是“Prompt 而已”。工具决定模型能做什么，权限限制行动边界，代码和测试负责验证结果。Prompt 则越来越像连接这些环节的接口，把人的意图传递给整个系统。

过去写代码，我们关心怎样实现。现在多了一层工作：怎样让模型准确理解，并用合理的成本实现。

所以，未来值得积累的，可能不只是代码，还有经过验证的任务描述、Context 组织方法和 Acceptance Criteria。一份好的 SKILL，像是把一次成功协作的经验保存下来，下次不用重新磨合。

这次一天做完小游戏，我感受到的是效率；看到花费，我开始思考效率的价格。

模型越强，表达就越值得认真对待。少一句歧义，少一次返工，省下的可能就是实实在在的时间和钱。

所谓“Prompt Economy”，也许就是从这里开始的：让每一次昂贵的计算，都更接近我们真正想要的结果。
